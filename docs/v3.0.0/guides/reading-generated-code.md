# Reading generated code

SourceFlow.Net v3 finds and wires domain types at **compile time**. The `SourceFlow.Generators` source generator ships inside the `SourceFlow.Net` package (ADR-004). It writes ordinary C# that you can read, step through in the debugger and review in pull requests. Nothing in command dispatch, event application or registration uses reflection (GAP-16).

This page shows where the generated files are and what each one contains.

## Where to find the files

Every project in this repository sets `EmitCompilerGeneratedFiles=true` (root `Directory.Build.props`), so generated files land on disk:

```text
obj/<Configuration>/net10.0/generated/
  SourceFlow.Generators/SourceFlow.Generators.SourceFlowGenerator/   ← SourceFlow output
  System.Text.Json.SourceGeneration/…/                               ← your module's JsonSerializerContext
```

In your own application, set the same property in the project file:

```xml
<PropertyGroup>
  <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
</PropertyGroup>
```

In Visual Studio and Rider, the files also appear under **Dependencies → Analyzers → SourceFlow.Generators**. *Go to definition* on a generated member opens them too.

Each file is named `<Namespace>.<Type>.<Kind>.g.cs`, for example `Bank.Accounts.BankAccount.Aggregate.g.cs`. Each one starts with `// <auto-generated/>`. Don't edit them: they're rebuilt on every compilation.

## What is generated

| You write | Kind | Generated |
|-----------|------|-----------|
| `[StronglyTypedId] partial record struct AccountId(Guid Value)` | `Id` | `New()` (UUIDv7), `Parse`/`TryParse`, `ToString` (`"D"`), `ToStreamSegment()` (`"N"`), formatting, a JSON converter |
| `[Aggregate("bank-account")] partial record BankAccount : IAggregate<…>` | `Aggregate` | `IAggregateRuntime`: `AggregateName`, `DecidedCommands`, `TargetingCommands`, a `Decide` switch over command types, `TargetOf` (the `[AggregateId]` member), and an `Evolve` switch over the `When` methods |
| `[Projection("account-summary")] partial class … : IDocumentProjection<TDoc, TKey>` | `Projection` | `HandledEvents`, `TryGetKey`, `FormatKey`, and an `Apply` switch over the `When` methods |
| `[ProcessManager("money-transfer")] partial record … : IProcessManager<…>` | `ProcessManager` | `HandledMessages`, a `TryCorrelate` switch over `CorrelateBy`, and a `React` switch |
| `[SourceFlowModule(typeof(MyJsonContext))] partial class MyModule` | `Module` | `Register`: every message type (sorted by name, with its kind), aggregate, projection, process manager and handler in the assembly, plus your JSON context |

### Example: an aggregate

From the Bank domain the tests use (`tests/Fixtures/Bank/Bank.Accounts/BankAccount.cs`):

```csharp
static Decision IAggregateRuntime<BankAccount, AccountId>.Decide(BankAccount state, ICommand command, in DecisionContext context)
{
    return command switch
    {
        CloseAccount c => state.Decide(c, context),
        Deposit c => state.Decide(c, context),
        OpenAccount c => state.Decide(c, context),
        Withdraw c => state.Decide(c, context),
        _ => throw new UnhandledMessageException(command.GetType()),
    };
}

public BankAccount Evolve(IEvent @event)
{
    return @event switch
    {
        AccountClosed e => When(e),
        AccountOpened e => When(e),
        MoneyDeposited e => When(e),
        MoneyWithdrawn e => When(e),
        _ => this,          // tolerant evolve: unknown events leave the state unchanged
    };
}
```

A few things to notice:

- **Dispatch is a `switch`, not reflection.** A command without a `Decide` isn't in the switch. Analyzer SF0006 warns about it at build time, and startup rejects it.
- **`Evolve` ignores events it doesn't know.** Analyzer SF0005 warns when your `Decide` produces an event that has no `When`, because that event would never change the state.
- **Lists are sorted.** Sorting makes the output deterministic, so review diffs stay small.

### Example: process manager correlation

`CorrelateBy` can return the id type itself, or a `string` that is parsed into the id. If the string doesn't parse, the message isn't correlated:

```csharp
case global::Bank.Transfers.TransferRequested m: id = CorrelateBy(m); return true;
case global::Text.CaseOpened m: return global::Text.CaseId.TryParse(CorrelateBy(m), out id);
```

## Analyzers that guard the generated code

Some diagnostics come from the same package (doc 03 §9):

| Id | Severity | Meaning |
|----|----------|---------|
| SF0001 / SF0002 | Error | A message has no `[MessageType]`, or a name and version are declared twice |
| SF0003 | Error | The command's target id member is missing or ambiguous (use `[AggregateId]`) |
| SF0004 / SF0007 / SF0009 | Error / Error / Warning | Purity: `When` with side effects, an async `Decide`, or a non-deterministic API in a pure method |
| SF0005 | Warning | `Decide` produces an event that has no `When` |
| SF0006 | Warning | A command has no `Decide` or handler |
| SF0008 | Error | An aggregate or process manager has the wrong shape (it must be a `sealed partial record` with `init` properties) |
| SF0010 | Error | A message or state type is missing from the module's `JsonSerializerContext`. **Code fix:** *Add `[JsonSerializable(typeof(T))]`* |
| SF0014 | Error | A command is handled locally and also routed with `routing.Command<T>().To(…)` (ADR-007) |

## Reviewing changes

Generated output is reproducible: the same sources always produce the same files. In this repository, the generated output of the Bank test fixture (`tests/Fixtures/Bank/Bank.Accounts`) is also kept as an approved snapshot (GEN-39). To see what a domain change does to the generated code, build and diff the `obj/…/generated` folder, or let the snapshot test show the change.

The generator is incremental. An edit that doesn't touch a SourceFlow type (`[Aggregate]`, `[Projection]`, `[ProcessManager]`, `[MessageType]`, `[StronglyTypedId]` or a module) produces no new generator work (GEN-38).
