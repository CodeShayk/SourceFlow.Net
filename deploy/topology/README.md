# Topology as code

These modules create a service's broker resources from its topology export, so production services can run with
`ProvisioningMode.Validate` and describe-only permissions (ADR-017, doc 07 §5).

```bash
dotnet sourceflow topology export --output accounts.topology.json
```

The export names every resource the transport would create, in the provider's own terms. A module only reads it; it
never computes a name, so the module and the service cannot disagree. `topology.schema.json` is the export's JSON Schema.

| Folder | Provider | Creates |
|--------|----------|---------|
| `terraform/aws` | Amazon SQS and SNS | Endpoint queue with a redrive policy to its dead-letter queue (FIFO when ordered), published topics, raw-delivery subscriptions with filter policies, and the queue policy for the subscribed topics. The `runtime_policy_json` output is the service's least-privilege IAM policy. |
| `terraform/gcp` | Google Cloud Pub/Sub | Command topic and subscription, dead-letter topic and subscription, published topics, one subscription per subscribed topic. Grants the Pub/Sub service agent what dead-lettering needs (`grant_service_agent`), and the service's identity what it needs at runtime (`runtime_member`, optional). |
| `terraform/azure` | Azure Service Bus | Endpoint queue, published topics, and a forwarding subscription per subscribed topic with its rules, in an existing namespace. |
| `bicep/servicebus.bicep` | Azure Service Bus | The same as `terraform/azure`, for Bicep and ARM deployments. |

## Using a module

```hcl
module "accounts_topology" {
  source   = "github.com/CodeShayk/SourceFlow.Net//deploy/topology/terraform/aws?ref=v3.0.0"
  topology = file("${path.module}/accounts.topology.json")
}
```

```bicep
module accounts 'servicebus.bicep' = {
  name: 'accounts-topology'
  params: {
    namespaceName: 'my-namespace'
    topology: loadJsonContent('accounts.topology.json')
  }
}
```

A topic belongs to the service that publishes it. The subscriber's module looks a subscribed topic up rather than
creating it, so apply the publisher's stack first. In a single stack holding every service, set
`create_subscribed_topics = true` (Bicep: `createSubscribedTopics`).

Each module checks that the export is for its provider and is schema version 1.

## Notes per provider

- **Azure.** ARM creates a match-everything rule called `$Default` with every subscription. The export names each
  subscription's first rule `$Default`, and the modules overwrite it rather than adding a rule beside it. The Terraform
  module uses `azapi_update_resource` for this. `Validate` compares the filters, not the rule names.
- **Azure permissions.** At runtime a service reads its queue's settings, which Service Bus allows only with the Manage
  right. Give the service Azure Service Bus Data Owner on its queue, or let it provision itself.
- **Google Cloud.** Pub/Sub accepts 5 to 100 delivery attempts. A lower limit is in the `sf-max-deliveries` label, and
  the receiver enforces it itself.

## Fixtures and tests

`fixtures/{transport}/*.json` are the exports of the conformance kit's topology fixtures (`TopologyFixtures` in
`SourceFlow.Testing`): an endpoint alone, the TCK provisioning topology, ordering, every kind of filter, and a publisher
and subscriber sharing a topic. They are generated by the libraries, and a test fails when they drift. To regenerate
them, run the cloud tests with `SOURCEFLOW_APPROVE=1`.

| Test | What it checks |
|------|----------------|
| `terraform test` in each `terraform/*` folder | Every fixture against mock providers: resource counts, settings, the wrong-provider check |
| IAC-01 | `terraform/aws` applied to LocalStack; the result passes the AWS transport's `Validate` |
| IAC-02 | `terraform/gcp` applied to the Pub/Sub emulator; the result passes the Google Cloud transport's `Validate` |
| IAC-03 | Runs each module's `terraform test` suite |
| IAC-04 | `bicep build` of the module for every Azure fixture |
| UT-TOP-12 | `ProvisionAsync(CreateIfMissing)` on each emulator creates every owned resource the export describes |

The Service Bus emulator has no ARM endpoint, so the Azure modules are not applied in CI. The mock-provider suite,
the Bicep build and UT-TOP-12 cover them instead.

The IaC tests run in the `iac` job of `v3-pr`. Locally they use `terraform` on the path, or, with `SOURCEFLOW_IAC=1`,
the pinned `hashicorp/terraform` image in Docker.
